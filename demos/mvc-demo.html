MVC Task Manager — Architecture in Action

This runs entirely in your browser (GitHub Pages can't host a live Node/Express/PostgreSQL backend), but it mirrors the exact separation of concerns used in the real project: a Controller that receives actions, a Model that owns the data, and a View that only renders. Every click on the left produces a real trace on the right, so you can see the architecture actually working, not just described.

View — Task List
    Request / Data Flow Trace
    Interact with the task list to see the Controller → Model → View flow.

    How to read it: adding a task fires Controller.create(), which validates the input, asks Model.tasks to persist a new record, and only then tells the View to re-render — the View never touches the data directly. That's the same rule this project follows: routes call controllers, controllers call models, views only display what they're given.
